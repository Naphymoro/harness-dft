# Band structure and DOS

## Prerequisites

- The structure must already be **relaxed** (run `dft-relax` first if not) — these workchains do SCF + bands/NSCF, not geometry optimization.
- For DOS/PDOS, three AiiDA codes are needed: `pw.x`, `dos.x`, `projwfc.x` (all registered separately in `verdi code list`).

## Band structure

```python
from harness_dft.workflows.bands_dos import build_bands_inputs
from aiida.engine import run_get_node

builder, scf_plan, bands_plan = build_bands_inputs(
    relaxed_atoms, code_label="pw-7.5@localhost",
    protocol="balanced", kpoints_mesh=(6, 6, 6), ecutwfc_ry=50.0,
)
results, node = run_get_node(builder)
```

The k-path for bands is auto-generated by seekpath inside the workchain — `kpoints_mesh` here only controls the SCF step's mesh, not the band path. Do not try to override `builder.bands.kpoints` directly; it's deliberately left to the workchain.

## Density of states / PDOS

```python
from harness_dft.workflows.bands_dos import build_pdos_inputs

builder, scf_plan, nscf_plan = build_pdos_inputs(
    relaxed_atoms,
    pw_code_label="pw-7.5@localhost",
    dos_code_label="dos-7.5@localhost",
    projwfc_code_label="projwfc-7.5@localhost",
    kpoints_mesh=(6, 6, 6),  # NSCF mesh defaults to 2x this if not given separately
)
results, node = run_get_node(builder)
```

## Reporting results

- Band gap: inspect `results['band_parameters']` (if metallic, expect zero/near-zero gap — cross-check against `harness_dft.structures.is_likely_metal`, which is only a coarse heuristic and can be wrong).
- Plot bands with `results['band_structure'].get_ase()`... or via ASE's `ase.dft.band_structure` after export, per the researched capability map.
- PDOS: `results['dos']` / `results['projections']` outputs from `PdosWorkChain`.

## Known gotchas

- **Not live-tested end-to-end** while building this harness (bands+DOS pipelines are much slower to iterate on than SCF/relax) — the builder construction and namespace paths (`builder.scf`, `builder.bands`, `builder.nscf`) were verified directly against the installed `aiida-quantumespresso` 4.17.0 source, but no actual run was executed. Treat the first real run as a validation step, not a known-good path — read `verdi process report` closely if anything looks off.
- Both `build_bands_inputs` and `build_pdos_inputs` call `apply_calculation_settings`/`apply_resource_plan` per sub-step (scf/bands/nscf each get their own resource plan) — check `scf_plan`/`bands_plan`/`nscf_plan` if resource usage looks wrong for one stage but not another.
